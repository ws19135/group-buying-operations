# Dashboard 規格（管理者／團主）

> 程式：`src/server/modules/dashboard.ts`（查詢）、`src/server/lib/kpi.ts`（口徑，**單一來源**）。測試：`tests/orders-dashboard.test.ts`、`tests/unit/kpi.test.ts`。

## 1. 資料來源與「即時」的定義

- 業績**只來自 `orders` 表**；沒有任何程式會自行產生或估算業績。
- 訂單目前只有一條進入路徑：**CSV 匯入**（`/imports`）。電商 API／Webhook 為 `BLOCKED`。
- 因此「即時」＝**最近一次匯入的資料截至時間**。畫面一律顯示：資料品質狀態、最近一次匯入（批次、來源、完成時間、資料截至時間）、警告清單。不宣稱秒級即時。
- `data_origin`：`IMPORT`（匯入）、`DEMO`（種子程式產生的虛構資料）、`MANUAL`（保留）。

| 資料品質狀態 | 條件 | 畫面 |
|---|---|---|
| `NO_DATA` | 可見範圍內沒有任何訂單 | 「待串接：尚無任何訂單資料」；所有業績 KPI 顯示「—」（值為 null，不是 0） |
| `DEMO` | 全部訂單都是 DEMO | 醒目橫幅：「DEMO 資料：…不是真實營運數字」 |
| `MIXED` | DEMO＋匯入混合 | 橫幅：「請勿作為正式業績」 |
| `IMPORT` | 全部來自匯入 | 一般提示 |

警告（`warnings`）：尚無資料；含 DEMO；有 N 筆匯入錯誤待處理；最近一次匯入為 PARTIAL／FAILED；最近資料超過 3 天未更新；（團主端）部分檔期尚未設定佣金費率。

## 2. KPI 口徑

| KPI | 公式 | 來源 |
|---|---|---|
| GMV | Σ `gross_amount`（狀態 PAID／PARTIAL_REFUND／REFUNDED；下單時間在本期） | orders |
| 退款金額 | Σ `refund_amount`（同範圍） | orders |
| 有效淨銷售額 | GMV − 退款金額 | 衍生 |
| 有效訂單數 | 狀態 PAID 或 PARTIAL_REFUND 的訂單數（全額退款不算） | orders |
| AOV | 有效淨銷售額 ÷ 有效訂單數（無有效訂單 → 無值） | 衍生 |
| 退款率 | 有退款的訂單數 ÷ 計入銷售的訂單數 | 衍生 |
| 目標達成率 | 與本期重疊且設有目標的檔期：累計有效淨銷售額 ÷ 目標合計（無目標 → 無值，不顯示 0%） | orders ÷ campaigns.target_revenue |
| 預估佣金 | 歸因有效淨銷售額 × 佣金費率，四捨五入到整數元；無費率規則 → 無值 | orders × commission_rules |

- `PENDING`（未付款）與 `CANCELLED` 不計入任何銷售指標。
- 歸因：`attributions.share_percent` 分攤；管理端另列「未歸因淨銷售」，避免「團主加總 ≠ 總額」無法解釋。
- 每個 KPI 物件都帶 `source` 與 `formula`（API 回傳 `kpiDefinitions`），UI 可直接顯示口徑。
- 期間：`?month=YYYY-MM`（台北日曆月），預設當月。

## 3. 管理者 Dashboard（`GET /api/dashboard/admin`）

| 區塊 | 內容 | 權限／範圍 |
|---|---|---|
| 資料品質 | 狀態、最近匯入、警告 | 全部 |
| 業績 KPI | GMV、退款、淨銷售、有效訂單、AOV、退款率 | 需 `order.read`（營運小編只含自己負責的檔期） |
| 目標達成 | 各檔期目標／累計淨銷售／達成率 | 同上；目標欄位需 `campaign.sensitive.read` 才會有資料來源 |
| 檔期管線 | 各狀態數量 | 資料範圍內檔期 |
| 近 30 天開團／結團 | 清單 | 同上 |
| 團主績效 | 各團主本期淨銷售、有效訂單（歸因分攤） | 同上 |
| 社群概況 | 各平台啟用中社群數、未來 7 天曝光安排數 | |
| 任務 | 未完成、逾期、今日到期、未指派、被封鎖、待核准 | 資料範圍內 |
| 逾期異常 | 前 20 筆逾期任務（含逾期天數） | |
| 例外 | 未結例外依嚴重度計數 | 需 `exception.read` |
| 待核准數 | | |
| 廠商合作進度 | 每家廠商進行中檔期數、任務完成比例、廠商任務逾期數 | |

## 4. 團主 Dashboard（`GET /api/dashboard/host`）

| 區塊 | 內容 |
|---|---|
| 我的檔期 | 進行中／即將開始（不含草稿與已取消）：狀態、日期、我的角色、**我的目標**、我的淨銷售、達成率、預估佣金（標「預估」與使用的規則） |
| 行事曆 | 未來 60 天：我的曝光安排、開團、結團 |
| 待辦 | 我的（HOST 角色）任務，含逾期標示；待回覆的邀請（可確認／婉拒） |
| 我的業績 | 本期 GMV、淨銷售、有效訂單（歸因分攤） |
| 預估佣金 | 合計與依據；**不等於正式結算** |
| 試用品與素材 | 寄樣、到貨試用、回饋、開團審核、圖文的任務狀態 |
| 結算進度 | 依檔期狀態顯示「尚未進入結算／履約結算準備中／已結算／已結案」；正式結算屬 Phase 2 |

- 團主只看得到**自己**的資料：其他團主的名稱、ID、目標、業績都不會出現（測試鎖住）。
- 內部人員可用 `?hostId=OWN-xxxx` 以團主視角預覽；測試驗證與團主本人看到的內容完全相同。

## 5. 不做的事（避免誤導）

- 不顯示成本、毛利、淨利（財務模組屬 Phase 2）。
- 不做預測或趨勢外推。
- 沒有訂單就不顯示業績數字。

## 管理者總覽：清單要看得出「是哪位團主、哪家廠商」（2026-10-28 補強）

來源：2026-11-03 討論前的使用回饋——只看到檔期名稱，還得再點進去確認是哪位團主的問題，無法即時反應。

| 區塊 | 新增內容 | 口徑 |
|---|---|---|
| 未來 30 天開團／結團 | 團主、廠商欄；一檔 30 天內既開團又結團時各列一列 | 團主＝該檔期未婉拒的團主（主要團主排前面）；未回覆者標「待回覆／未回覆」 |
| 逾期任務 | 團主、廠商、卡在誰（負責角色）欄 | 任務屬於檔期，因此顯示該檔期的團主；多位團主時全部列出 |
| 廠商合作進度（逐檔） | 廠商、檔期、狀態、團主、完成度（完成／總任務）、下一個任務（負責角色與日期）、逾期數（含廠商自己的逾期） | 下一個任務＝該檔期未完成任務中預定完成日最早者；完成度不計已略過／已取消任務 |

限制：任務目前是「一檔一份」，不是每位團主一份（FEATURE_STATUS #15）；因此多團主的檔期，逾期任務會列出所有參與團主，無法指出是其中哪一位。若要精確到單一團主，需把團主任務拆成每位團主一份（尚未做，列入待決）。

權限：僅有 `dashboard.admin` 的內部角色看得到；團主與廠商角色不能開這個總覽（測試鎖住）。

## 營運主管總覽：與建置前介面示意的對照與補齊（2026-10-29）

依據：建置前的 Dashboard 介面示意（管理者需要跨團分析與異常決策、團主需要立即看懂「我的團賣得怎麼樣、接下來做什麼」；示意含 KPI 卡、跨團主業績比較、營運異常與待辦、KPI 清單與資料更新原則）。本表逐項對照目前的營運主管總覽。

| 示意中的項目 | 現況 | 說明 |
|---|---|---|
| 管理者與團主不使用同一個 Dashboard | ✅ 原本就有 | `/dashboard`（管理者）與 `/dashboard/host`（團主），權限與欄位不同 |
| 標題＋「本週／本月」切換 | ✅ 已補 | 本週＝台北時間週一到週日；本月保留上月／下月切換 |
| KPI：累計有效銷售額（已扣退款，未必等於已收款） | ✅ 原本就有 | 「有效淨銷售額」；口徑可展開 |
| KPI：進行中檔期（跨 N 位團主） | ✅ 已補 | 狀態為已排程、進行中、待結單確認、履約中、待結算的檔期；跨幾位未婉拒的團主 |
| KPI：預估分潤（尚待結算確認） | ✅ 已補（名稱用「預估佣金」） | 重用團主 Dashboard 與結算試算的同一個函式；沒有費率的團主不猜，標「N 筆尚未設定費率」。**不套用招財兔分潤公式**（ADR） |
| KPI：待處理異常（逾期 N／待審核 N） | ✅ 原本就有 | 「逾期任務」「待核准」「未結例外」三張卡分開顯示，各自可點進去 |
| 跨團主業績比較（長條圖） | ✅ 已補 | 依歸因的有效淨銷售額，最多 8 位；點長條進團主頁；原本只有表格，表格保留 |
| 營運異常與待辦（依緊急程度排序） | ✅ 已補 | 彙整逾期任務、團主未回覆、未結例外、結單後缺訂單資料、待核准；標題為「廠商｜事件」；每類最多 5 筆，總共 12 筆；自動化產生的「任務逾期」「團主未回覆」例外不重複列出 |
| KPI 清單：有效 GMV／訂單數、目標達成率、團主貢獻排行、超期任務數 | ✅ 原本就有 | |
| KPI 清單：社群業績排行 | ✅ 已補 | 訂單需帶社群編號才會歸因 |
| KPI 清單：每檔團購產值 | ✅ 已補 | 有訂單的檔期數、平均每檔有效淨銷售額、各檔排行 |
| KPI 清單：廠商合作成功率 | ⚠️ 已補（**暫定口徑，待 Owner 確認**） | 已開團檔期 ÷（已開團＋已取消）；評估中、籌備中不計 |
| KPI 清單：檔期準時開團率 | ⚠️ 已補（**暫定口徑，待確認**） | 實際轉為「進行中」的日期不晚於預定開團日；需要系統內的狀態轉換紀錄，沒有紀錄就顯示「資料不足」，不編造 |
| KPI 清單：預估分潤與已確認佣金 | ✅ 已補 | 已確認佣金＝本期已確認結算的佣金（覆寫優先）。結算口徑仍待 Owner 確認 |
| KPI 清單：商品復開績效 | ⚠️ 已補（**暫定口徑，待確認**） | 出現在 2 檔以上（不含已取消）的商品；累計有效淨銷售額（品項金額依訂單退款比例折算）與平均每檔 |
| 有效 GMV、預估佣金、已確認佣金、已收款金額必須是不同指標 | ✅ 已補 | 四張卡分開，並在畫面上標明「不同的指標，請勿混稱為業績」；已收款金額＝本期有效的入帳紀錄（人工入帳） |
| 每個 KPI 可點進明細、看來源、同步時間與計算方式 | ✅ 已補 | 業績與財務卡片有「看明細 →」；新增「訂單明細」頁（可依檔期、狀態、日期、團主、退款篩選）；「口徑」可展開；資料來源與最後同步見下 |
| 資料更新：匯入後更新並顯示最後同步時間 | ✅ 原本就有＋已補 | 頁首有最後匯入與資料截至；新增「資料來源與同步」表（來源、性質、訂單數、最後同步、最近訂單） |
| 資料更新：沒有訂單明細的合作標示「廠商回報／人工確認」 | ✅ 已補 | 資料性質欄：DEMO 示範／匯入檔／廠商回報或人工確認 |
| 資料更新：支援 API／Webhook 事件同步並定期核對 | ⛔ 未做（BLOCKED） | 尚未決定訂單來源平台，也沒有憑證 |

權限：預估佣金需要 `commission.read`，已確認佣金與已收款金額需要 `finance.read`（營運小編沒有，所以不顯示這三項）；業績相關項目需要 `order.read`。

仍待 Owner 決定：廠商合作成功率、檔期準時開團率、商品復開績效的口徑；結算與佣金口徑（見 FINANCE.md）；訂單來源（API／Webhook）。
