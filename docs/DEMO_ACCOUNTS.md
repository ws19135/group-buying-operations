# 示範帳號與權限（僅限虛構 DEMO 資料）

所有帳號由 `npm run db:seed:demo` 建立，網域為 `example.invalid`（不存在的網域，不會寄出任何信）。**密碼是 `.env.local` 的 `DEMO_PASSWORD`，不要寫進任何文件或 repo。**

| 帳號 | 角色 | 建議給誰看／用途 | 看得到 | 看不到／不能做 |
|---|---|---|---|---|
| `demo-admin@example.invalid` | 系統管理者 | 管理者 | 全部，含使用者管理、稽核、自動化 | — |
| `demo-manager@example.invalid` | 營運主管 | 討論流程、核准關卡（G1–G5） | 除使用者管理與佣金規則設定外的全部，含成本、目標營收、稽核 | 不能管理使用者、不能改佣金規則 |
| `demo-editor@example.invalid` | 營運小編 | 日常建檔、排檔期、派任務 | 廠商、團主、商品、檔期的新增與編輯、申請核准、訂單匯入 | 成本、目標營收、稽核、佣金；不能做核准決定 |
| `demo-finance@example.invalid` | 財務 | 看結算與成本口徑 | 成本、目標營收、訂單、佣金（可設定）、稽核；G3／G4 核准 | 不能編輯廠商／團主／檔期 |
| `demo-host1@example.invalid`、`demo-host2@example.invalid` | 團主 | 看團主視角 | 只看自己被指派的檔期、任務、自己的儀表板與預估佣金 | 其他團主的資料（會回 404）；成本、內部備註 |
| `demo-vendor@example.invalid` | 廠商 | 看廠商視角 | 只看自己品牌的商品、檔期與任務，可回填自己的任務 | 其他廠商的資料；成本、佣金、內部備註 |

## 給同事的建議看法
1. 先用營運主管看儀表板與檔期時間軸，再看一個檔期的 15 步流程與核准關卡。
2. 用營運小編改一個日期，看「重排預覽 → 確認」。
3. 用團主與廠商帳號登入，確認他們看不到成本與其他人的資料。
4. 用營運主管開「團主 → 小雅媽咪」看客群分析（事實／估計／未知），再到商品「家庭除菌洗衣精」按「產生候選團主評估」、到「客群適配」覆核一筆（營運小編可評估但不能覆核；團主、廠商、財務看不到客群與適配）。
5. 用營運主管開「選品與試用」總覽，再到廠商「晴空保養」看已核准的合作資格審查（12 類、證據、法務標示）、商品「保濕面膜」看選品評估／試用／可行性、檔期「保濕面膜試用團」的「選品與試用」分頁（G1 決策摘要）。換營運小編登入，確認看不到分潤條款與成本、利潤（顯示「無權限」）；團主、廠商看不到選品與試用。

## 注意
- 資料全是虛構（名稱帶 `[DEMO]`），同事可以隨意編輯；還原方式見 [DEMO_DEPLOYMENT.md](DEMO_DEPLOYMENT.md)。
- 自動化預設全關，通知只進測試佇列，不會真的寄出。
- 權限定義以 `src/server/lib/permissions.ts` 為準，本表若不同以程式為準。
