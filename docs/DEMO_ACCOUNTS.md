# 示範帳號與權限（僅限虛構 DEMO 資料）

所有帳號由 `npm run db:seed:demo` 建立，網域為 `example.invalid`（不存在的網域，不會寄出任何信）。**密碼是 `.env.local` 的 `DEMO_PASSWORD`，不要寫進任何文件或 repo。**

| 帳號 | 角色 | 建議給誰看／用途 | 看得到 | 看不到／不能做 |
|---|---|---|---|---|
| `demo-admin@example.invalid` | 系統管理者 | 管理者 | 全部，含使用者管理、稽核、自動化 | — |
| `demo-manager@example.invalid` | 營運主管 | 討論流程、核准關卡（G1–G5） | 除使用者管理與佣金規則設定外的全部，含成本、目標營收、稽核 | 不能管理使用者、不能改佣金規則 |
| `demo-editor@example.invalid` | 營運小編 | 日常建檔、排檔期、派任務 | 廠商、團主、商品、檔期的新增與編輯、申請核准、訂單匯入 | 成本、目標營收、稽核、佣金；不能做核准決定 |
| `demo-finance@example.invalid` | 財務 | 看結算與成本口徑 | 成本、目標營收、訂單、佣金（可設定）、稽核；G3／G4 核准 | 不能編輯廠商／團主／檔期 |
| `demo-host1@example.invalid`、`demo-host2@example.invalid` | 團主 | 看團主視角 | 只看自己被指派的檔期、任務、自己的儀表板與預估佣金 | 其他團主的資料（會回 404）；成本、內部備註 |
| `demo-vendor@example.invalid` | 廠商 | 看廠商視角 | 只看自己品牌的商品、檔期與任務，可回填自己的任務 | 其他廠商的資料；成本、佣金、內部備註 |

## 給同事的建議看法
1. 先用營運主管看儀表板與檔期時間軸，再看一個檔期的 15 步流程與核准關卡。
2. 用營運小編改一個日期，看「重排預覽 → 確認」。
3. 用團主與廠商帳號登入，確認他們看不到成本與其他人的資料。
4. 用營運主管開「團主 → 小雅媽咪」看客群分析（事實／估計／未知），再到商品「家庭除菌洗衣精」按「產生候選團主評估」、到「客群適配」覆核一筆（營運小編可評估但不能覆核；團主、廠商、財務看不到客群與適配）。
5. 用營運主管開「選品與試用」總覽，再到廠商「晴空保養」看已核准的合作資格審查（12 類、證據、法務標示）、商品「保濕面膜」看選品評估／試用／可行性、檔期「保濕面膜試用團」的「選品與試用」分頁（G1 決策摘要）。換營運小編登入，確認看不到分潤條款與成本、利潤（顯示「無權限」）；團主、廠商看不到選品與試用。
6. 跑 `npm run db:seed:demo:collaboration` 後，用營運主管開「合作管理 → 網紅合作申請」看 6 筆申請與樣品進度（含補寄），再用團主帳號看「團主工作台 → 我的樣品申請」、廠商帳號看「廠商工作台 → 網紅申請與樣品寄送」，確認各自只看得到自己的；最後用廠商帳號匯出表單二，確認收件人／電話／地址是 `［無權限］`（財務帳號完全看不到這個模組）。

## 合作申請與樣品管理（2026-11-06 新增，看得到的東西變了）

新增 11 項 `collaboration.*` 權限後，示範帳號在「合作申請」裡看到的範圍由兩個新的分權維度決定，和既有的檔期資料範圍是分開的：

- **`collaboration.self`（只看自己）**：團主與廠商沒有 `collaboration.read`，改以這項權限只看得到自己名下的申請；別人的申請一律 404／403。團主與廠商都可以自己建立申請（`collaboration.create`）。
- **`collaboration.pii.read`（收件個資）**：收件人姓名／電話／地址存在獨立的資料表，只有管理者、營運主管、營運小編讀得到；申請詳情 API 完全不回傳收件內容，必須另外呼叫收件端點，每次成功讀取寫一筆稽核。廠商刻意有匯出權限但**沒有** `collaboration.pii.read`，所以廠商匯出時三格顯示 `［無權限］`；廠商要看到收件資訊，還得同時滿足「未清除＋申請已核准＋團主已確認可用＋未過保留期」。

| 帳號 | 在合作申請裡看得到／能做 |
|---|---|
| `demo-admin@example.invalid` | 全部，含收件個資、匯出、檔期關聯、到期個資清除（只有管理者能清除） |
| `demo-manager@example.invalid` | 全部案件、收件個資、匯出、檔期關聯；內部審核與正式合作確認的核准決策 |
| `demo-editor@example.invalid` | 全部案件、收件個資、匯出、檔期關聯、代廠商回填供樣、追蹤寄送；**刻意不能做核准決策**（`collaboration.review` 留給主管） |
| `demo-finance@example.invalid` | 完全看不到合作申請（財務刻意沒有任何 `collaboration.*` 權限） |
| `demo-host1@example.invalid`、`demo-host2@example.invalid` | 只看自己的樣品申請與寄送進度、確認收件、填自己的開團意願；看不到別人的申請，也看不到內部用的投廣與合作備註欄位 |
| `demo-vendor@example.invalid` | 只看自己品牌的申請、供樣審核、建立與更新寄送紀錄、匯出（收件個資遮罩） |

示範資料另外用 `npm run db:seed:demo:collaboration` 建立（冪等、可重複跑，偵測到 production 會直接拒絕）：**6 筆申請、4 筆寄送紀錄（含補寄）**，涵蓋待審、已核准待寄、已送達待回覆意願、已確認合作等情境。DEMO 的收件資訊全是**保留測試號碼**與 `example.invalid` 網域，沒有任何真實個資。

## 注意
- 資料全是虛構（名稱帶 `[DEMO]`），同事可以隨意編輯；還原方式見 [DEMO_DEPLOYMENT.md](DEMO_DEPLOYMENT.md)。
- 自動化預設全關，通知只進測試佇列，不會真的寄出；合作申請模組本身不產生任何通知（「後台設定 Mail」只記錄聯絡信箱與設定狀態）。
- 權限定義以 `src/server/lib/permissions.ts` 為準，本表若不同以程式為準。
