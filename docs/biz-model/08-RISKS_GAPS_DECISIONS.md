# 08 風險、缺口與 Owner 決策清單

> **狀態：PROPOSED。** 這是「一次性」的 Owner 決策彙整：01～07 與看板線框圖文件中所有 `【決策 B-xx】` 集中在這裡，不需要逐份回頭找。
> 在 Owner 回覆之前，所有「預設」只是文件採用的暫定做法，**不是核准規則**；沒有任何一項已寫進程式或改動已核准的 SRS／SAD／SDD。

## 1. 先講結論

1. **最先要決定的是 9 件事（§3.1）**——它們決定金額公式與資料模型，不決定就不能開工 P-A～P-C：分潤基礎（B-01）、階梯累進方式（B-02）、保底抵佣／加佣定義（B-03）、跨期退款處理（B-04）、公司收入認列（B-08，需會計師）、分潤付款方（B-09）、主模式規則（B-28）、費用規則核准流程（B-42）、看板退款期間口徑（B-38）。
2. **不需要現在決定**的事很多（BD CRM、快照頻率、對外報表）：文件都給了預設，可以先做不碰決策的 P-A（合作案與模式分類），其餘等回覆。
3. **有三件事不能由我們自己決定**：公司收入認列與稅務（會計師）、薦證揭露責任（法務）、撥款與金流（Owner 另行授權，系統不接金流）。
4. 最大的**技術缺口**是「退款事件日期」：現行 `orders.refund_amount` 只有累計值，沒有退款發生日，所以跨期退款更正與「退款當期」口徑都做不出來（缺口 G-02）。
5. 目前所有驗證都是**離線**：公式由 28 項算例證明自洽（[04](04-FINANCE_AND_COMMISSION.md) §9），沒有接資料庫、沒有真實資料、沒有真實合約條件。
