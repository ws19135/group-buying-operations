# 已知問題與限制

> 這份清單只寫「我確實知道」的限制與取捨；沒有列出的不代表沒有問題。嚴重度：🔴 上線前必須處理｜🟡 建議處理｜🟢 可延後。

## 安全與營運

| # | 級 | 問題 | 影響 | 建議 |
|---|:-:|---|---|---|
| K1 | 🔴 | 無 SSO／MFA、無密碼重設、無首次登入強制改密碼 | 管理者帳號只靠密碼 | 先決定身分機制（ADR-006）再上線 |
| K2 | 🔴 | 無備份排程與**還原演練**；未做靜態加密、RLS | 資料遺失風險 | 上線前建立備份＋實際還原演練 |
| K3 | 🟡 | 登入限流為單機記憶體 | 多實例部署時限流不共用（帳號鎖定在資料庫，不受影響） | 改用共用儲存 |
| K4 | 🟡 | `SESSION_SECRET` 目前未被任何簽章使用（session 為隨機 token＋資料庫雜湊） | 設定了也沒作用，容易誤會 | 要嘛移除要嘛用於 cookie 簽章 |
| K5 | 🟡 | 沒有監控／告警；只有 `GET /api/health` 與 `automation_runs` | 失敗要人去看 | 接上監控並對 `automation_runs.status=FAILED`、DEAD 通知告警 |
| K6 | 🟡 | `Idempotency-Key` 紀錄不會自動清理（`idempotency_keys` 持續成長） | 長期佔空間 | 加定期清理（Phase 2） |
| K7 | 🟡 | 沒有匿名／公開入口（刻意）；廠商只能由內部人員代為登錄 | 廠商無法自助回填 | 需 Owner 解凍並另行設計單一範圍入口 |

## 功能限制

| # | 級 | 問題 | 說明 |
|---|:-:|---|---|
| K8 | 🟡 | HOST／VENDOR 任務是「一檔一個」，不是「每位團主一個」 | 一檔多團主時，任一位團主帳號都能完成共用的團主任務（如試用回饋）；也因此「團主未回覆」是以任務逾期推定，並對該檔所有未回覆的團主開例外 |
| K9 | 🟡 | 手動鎖定單一任務日期後，下游任務不會立即連動 | 要再走一次「日期變更影響預覽」才會重排；預覽會把它列為受影響 |
| K10 | 🟡 | 預設模板只能「調整天數參數」發佈新版本，沒有步驟編輯器 | 改流程步驟需要改程式或新增 migration／資料 |
| K11 | 🟡 | 衝突偵測的「團主同時進行檔期上限」固定為 2 | 尚不可由設定調整 |
| K12 | 🟡 | G4（結算確認）只能人工確認；結算試算／佣金結算／調整批次未做 | Phase 2；檢查項會明示「結算試算尚未實作」 |
| K13 | 🟡 | 預估佣金＝單一費率×歸因淨銷售 | 不含階梯、扣項、含稅／未稅差異；**不是正式分潤**，畫面一律標「預估」 |
| K14 | 🟡 | 訂單只能 CSV 匯入；無訂單明細頁；每次匯入上限 2 MB／20,000 列 | 電商 API／Webhook＝BLOCKED |
| K15 | 🟡 | 訂單 `buyer_ref` 僅為去識別化代號，系統不驗證呼叫端是否真的去識別化 | 匯入前需人工確保檔案不含姓名／電話／地址 |
| K16 | 🟡 | 目標達成率以「與本期重疊檔期的累計淨銷售」計算，期間定義待 Owner 確認（ADR-010） | 跨月檔期可能與直覺不同 |
| K17 | 🟢 | `agreements` 只有 Schema，沒有介面 | 合作協議管理屬後續 |
| K18 | 🟢 | 商品素材只存連結，沒有檔案上傳與版本管理 | |
| K19 | 🟢 | 搜尋使用 `ILIKE`（無全文檢索）；列表最多 200 筆／頁 | 資料量大時需索引或全文檢索 |
| K20 | 🟢 | Dashboard 為即時查詢，沒有快取／每日快照（結單快照未做） | 資料量大時需優化；來源平台改值會影響歷史數字 |
| K21 | 🟢 | 團主帳號若綁定多位團主，Dashboard 預設顯示第一位（可用 `hostId` 切換） | UI 切換器依實作而定 |
| K22 | 🟢 | 只有繁體中文；未做無障礙（a11y）審查 | |

## 測試與驗證的限制

| # | 問題 | 說明 |
|---|---|---|
| T1 | 整合測試使用本機 PostgreSQL 16；CI 使用 `postgres:16` service | 尚未在其他版本驗證 |
| T2 | E2E 煙霧測試只在本環境預裝的 Chromium 驗證，未做跨瀏覽器 | |
| T3 | 沒有負載／壓力測試、沒有 SAST。`npm audit`（2026-10-28）：**正式相依** zod 3.25 有 1 個 high（超大集合驗證耗記憶體；修正需升到 zod 4，屬破壞性升級；已以 4 MB 請求上限＋各陣列 `.max()` 降低風險）、next 15.5 經 postcss 有 1 moderate／1 high（建置期 CSS 處理；修正需升到 next 16，屬主版本升級）；**僅開發用** vitest／tinypool 有 critical（測試執行器，不隨產品部署） | 上線前評估升級 zod 4、next 16，並在 CI 加入 `npm audit --omit=dev` |
| T4 | 與真實歷史結案數字的手工對帳（RM P3 Exit）無法進行 | 沒有真實資料（BLOCKED） |
| T5 | 所有業績數字測試都使用虛構資料；KPI 口徑（ADR-010）尚未經 Owner／財務確認 | |
