# 已知問題與限制

> 這份清單只寫「我確實知道」的限制與取捨；沒有列出的不代表沒有問題。嚴重度：🔴 上線前必須處理｜🟡 建議處理｜🟢 可延後。

## 安全與營運

| # | 級 | 問題 | 影響 | 建議 |
|---|:-:|---|---|---|
| K1 | 🔴 | 無 SSO／MFA、無密碼重設、無首次登入強制改密碼 | 管理者帳號只靠密碼 | 先決定身分機制（ADR-006）再上線 |
| K2 | 🔴 | 無備份排程與**還原演練**；未做靜態加密、RLS | 資料遺失風險 | 上線前建立備份＋實際還原演練 |
| K3 | 🟡 | 登入限流為單機記憶體 | 多實例部署時限流不共用（帳號鎖定在資料庫，不受影響） | 改用共用儲存 |
| K4 | ✅ | （已處理）`SESSION_SECRET` 從未被任何程式使用（session 為隨機 token＋資料庫雜湊），已移除設定項、文件說法與 CI／部署設定；舊環境殘留的該變數無影響 | — | 若日後改用簽章 cookie 再重新引入 |
| K5 | 🟡 | 沒有監控／告警；只有 `GET /api/health` 與 `automation_runs` | 失敗要人去看 | 接上監控並對 `automation_runs.status=FAILED`、DEAD 通知告警 |
| K6 | ✅ | （已處理）`idempotency_keys` 超過 30 天的紀錄由每日自動化工作 `daily_summary` 清除（預設停用，需管理者啟用；清除筆數記在該次執行的 `stats`）；這是技術性快取的實體刪除，不是業務資料 | — | 若想獨立排程，可拆成專用工作 |
| K7 | 🟡 | 沒有匿名／公開入口（刻意）；廠商只能由內部人員代為登錄 | 廠商無法自助回填 | 需 Owner 解凍並另行設計單一範圍入口 |

## 功能限制

| # | 級 | 問題 | 說明 |
|---|:-:|---|---|
| K8 | 🟡 | HOST／VENDOR 任務是「一檔一個」，不是「每位團主一個」 | 一檔多團主時，任一位團主帳號都能完成共用的團主任務（如試用回饋）；也因此「團主未回覆」是以任務逾期推定，並對該檔所有未回覆的團主開例外 |
| K9 | 🟡 | 手動鎖定單一任務日期後，下游任務不會立即連動 | 要再走一次「日期變更影響預覽」才會重排；預覽會把它列為受影響 |
| K10 | 🟡 | 預設模板只能「調整天數參數」發佈新版本，沒有步驟編輯器 | 改流程步驟需要改程式或新增 migration／資料 |
| K11 | 🟡 | 衝突偵測的「團主同時進行檔期上限」固定為 2 | 尚不可由設定調整 |
| K12 | 🟡 | G4（結算確認）只能人工確認；結算試算／佣金結算／調整批次未做 | Phase 2；檢查項會明示「結算試算尚未實作」 |
| K13 | 🟡 | 預估佣金＝單一費率×歸因淨銷售 | 不含階梯、扣項、含稅／未稅差異；**不是正式分潤**，畫面一律標「預估」 |
| K14 | 🟡 | 訂單只能 CSV 匯入；無訂單明細頁；每次匯入上限 2 MB／20,000 列 | 電商 API／Webhook＝BLOCKED |
| K15 | 🟡 | 訂單 `buyer_ref` 僅為去識別化代號，系統不驗證呼叫端是否真的去識別化 | 匯入前需人工確保檔案不含姓名／電話／地址 |
| K16 | 🟡 | 目標達成率以「與本期重疊檔期的累計淨銷售」計算，期間定義待 Owner 確認（ADR-010） | 跨月檔期可能與直覺不同 |
| K17 | 🟢 | `agreements` 只有 Schema，沒有介面 | 合作協議管理屬後續 |
| K18 | 🟢 | 商品素材只存連結，沒有檔案上傳與版本管理 | |
| K19 | 🟢 | 搜尋使用 `ILIKE`（無全文檢索）；列表最多 200 筆／頁 | 資料量大時需索引或全文檢索 |
| K20 | 🟢 | Dashboard 為即時查詢，沒有快取／每日快照（結單快照未做） | 資料量大時需優化；來源平台改值會影響歷史數字 |
| K21 | 🟢 | 團主帳號若綁定多位團主，Dashboard 預設顯示第一位（可用 `hostId` 切換） | UI 切換器依實作而定 |
| K22 | 🟢 | 只有繁體中文；未做無障礙（a11y）審查 | |

| T2 | E2E 煙霧測試只在本環境預裝的 Chromium 驗證，未做跨瀏覽器 | |
| T3 | 沒有負載／壓力測試、沒有 SAST。`npm audit`（2026-10-28）：**正式相依** zod 3.25 有 1 個 high（超大集合驗證耗記憶體；修正需升到 zod 4，屬破壞性升級；已以 4 MB 請求上限＋各陣列 `.max()` 降低風險）、next 15.5 經 postcss 有 1 moderate／1 high（建置期 CSS 處理；修正需升到 next 16，屬主版本升級）；**僅開發用** vitest／tinypool 有 critical（測試執行器，不隨產品部署） | 上線前評估升級 zod 4、next 16，並在 CI 加入 `npm audit --omit=dev` |

## Phase 2（履約、售後、財務）新增限制

| # | 級 | 問題 | 影響 | 建議 |
|---|:-:|---|---|---|
| P2-1 | 🟡 | 結算只重用既有佣金口徑；階梯、扣項（運費、平台費）、退款扣回時點、分潤比例與順序都未做，只能用「覆寫」與「調整項」（皆需原因） | 結算數字僅供討論，不可作為付款依據 | Owner 定義口徑後再實作；碰金額公式一律先問 |
| P2-2 | 🟡 | 結算確認不會自動推進檔期 G4 或狀態 | 需人工在檔期核准頁處理 | 待 Owner 決定是否串接 |
| P2-3 | 🟡 | 退款寫回訂單後，再匯入較舊 CSV 會覆蓋 `refund_amount` | 退款金額可能被舊檔蓋回 | 流程規避：來源已反映退款就不要勾「寫回」；或匯入改為只增不減 |
| P2-4 | 🟢 | 庫存異動不隨出貨自動扣；團主／廠商不能自行簽收 | 需內部人員代登 | 廠商入口解凍後再做 |
| P2-5 | 🟢 | 逾期售後案件只在畫面標示，未接例外自動化 | 不會自動通知 | 接入例外管理 |
| P2-6 | 🟢 | 發票、銀行對帳只有人工紀錄 | 無自動比對 | 待 Owner 決定發票與金流服務 |

## SOP 01（客群分析與商品適配）新增限制

| # | 級 | 問題 | 影響 | 建議 |
|---|:-:|---|---|---|
| S1-1 | 🟡 | 評分權重（30/20/15/20/15）與門檻（80／65）是**建議值，待 Owner 確認** | 建議等級可能與實務不符 | 決策 D-18；可在 `/fit?tab=config` 調整，版本與稽核留存 |
| S1-2 | 🟡 | 需求維度是關鍵字比對，可能漏判同義詞；一律標為估計 | 需求分數可能偏低或偏高 | 人工覆核；別名表由程式維護（D-22） |
| S1-3 | 🟡 | 歷史績效在已結單檔期不足時為未知；比較基準是全體平均，不含季節因素 | 新團主常顯示未知 | 累積資料後自然改善 |
| S1-4 | 🟢 | 「資料已更新」只看商品／規格／廠商／客群的更新時間，不含訂單與出貨變動 | 歷史績效與供應履約變動不會提示重評 | 需要時手動重新評估 |
| S1-5 | 🟢 | G1 不納入適配檢查，只供查閱；結案回寫需手動按鈕 | 不會自動提醒 | 決策 D-19、D-20 |
| S1-6 | 🟢 | 沒有問卷、平台統計等外部資料匯入；事實／估計由填寫者標示 | 事實的可信度取決於來源說明 | 決策 D-24 |

## SOP 02／03（選品、合作資格審查、試用、可行性）新增限制

| # | 級 | 問題 | 影響 | 建議 |
|---|:-:|---|---|---|
| S2-1 | 🟡 | 評分權重（25/25/20/15/10/5）、門檻（80／65）、有效期（審查 365 天、資格試用 180 天）是**建議值，待 Owner 確認** | 建議等級與失效時間可能與實務不符 | 決策 D-25、D-27；`/selection?tab=config` 可調整，版本與稽核留存 |
| S2-2 | 🟡 | 「疑似受規範品類」是關鍵字比對，會漏判也會誤判；系統只標示需法務或合規審查，**不判斷合法** | 受規範商品可能沒被標示 | 建立調查時明確選受規範品類；受規範品類清單與審查窗口待 Owner 指定（D-29） |
| S2-3 | 🟡 | 可行性試算口徑（公司營業收入、分潤基礎、付款方）沿用 biz-model 04 的提案，只支援單一費率＋固定費 | 階梯、保底、更正等尚未納入 | 決策 D-31；待費用規則落地 |
| S2-4 | 🟡 | 證據只存連結：連結失效不會被偵測；網域白名單預設不限制 | 可能指向已失效或不該放的位置 | 決策 D-32；指定雲端與網域後設定白名單；檔案不得放進 GitHub |
| S2-5 | 🟢 | 選品結果不納入 G1 檢查，只在決策摘要查閱；商品送審前不要求有評估（D-26、D-33） | 不會擋下風險高的商品 | 待 Owner 決定 WARN／BLOCK |
| S2-6 | 🟢 | 試用品回收逾期只記錄、不提醒（D-34）；試用不自動完成寄樣／回饋任務 | 需人工追蹤 | 接入例外管理或任務 |
| S2-7 | 🟢 | 商品指紋不含價格；價格改變不使資格失效。可行性實際回寫的客訴與出貨例外是檔期層級，不分團主 | 價格大幅變動時仍沿用舊資格 | 需要時重做資格試用 |
| S2-8 | 🟢 | 可行性新版本是「在上一版上套用這次填寫的欄位」，介面不支援把已填欄位清回「未知」（API 可傳 null） | 需要清除時要用 API | 後續補介面 |
