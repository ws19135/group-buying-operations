# 2026-11-03 內部討論說明（給老闆與同事）

> 本頁所有畫面與數字都是虛構 DEMO 資料（名稱帶 `[DEMO]`）。系統尚未上線，未接任何真實訂單、通知或金流。簡報檔另附（同內容的 15 頁版本）。

## 1. 一句話
團購營運系統已能在瀏覽器完整走過「廠商進件 → 排檔期 → 五道核准關卡 → 履約出貨 → 售後 → 財務結算試算」。今天要決定的是：**哪些做法要配合現況調整，以及金額口徑與資料來源由誰來定。**

## 4. 建議示範動線（約 15 分鐘）
1. 營運主管登入：儀表板 → 檔期清單 → 打開一檔，看 15 步時間軸與「下一步」提示（3 分）
2. 改一個日期，看影響預覽與連動（2 分）
3. 核准頁：走一次 G1 或 G2，看系統檢查擋下與放行的差別（2 分）
4. 履約出貨：包裝 → 出貨 → 送達 → 簽收（2 分）
5. 售後：開退款申請 → 核准 → 財務完成（2 分）
6. 財務：開結算試算 → 加調整項 → 確認後鎖定（3 分）
7. 換團主、廠商帳號各看一眼：只看得到自己的範圍（1 分）

帳號與權限見 [DEMO_ACCOUNTS.md](DEMO_ACCOUNTS.md)。示範前請先確認網址可開、帳號可登入；網路出問題時，[各角色實際畫面截圖](wireframes/AS_BUILT_SCREENS.md)可作備用。

## 7. 請在會中決定的事
**金額與資料**
1. **結算口徑**：運費、平台費、階梯費率、退款扣回時點、分潤比例與順序如何定？（系統不會自行發明金額公式）
2. **結算確認要不要自動推進 G4**：目前結算確認後仍須人工到檔期核准頁處理。
3. **訂單從哪裡來**：哪個平台、用 API 還是定期匯出檔？目前只有 CSV 匯入。
4. **試點範圍**：先選哪幾位團主、哪一檔已結案案例，與現行做法手工對帳。

**營運規則與上線前提**
5. **金流模式與責任**：發票與退款由誰負責？目前系統只做人工紀錄。
6. **退款核准規則**：核准者可否是申請者本人？「等待廠商」狀態要不要保留？
7. **誰能看什麼**：廠商可否看售後案件？團主可否看自己的目標營收與備註？
8. **上線前提**：登入方式（SSO／MFA）、備份還原演練、何時解凍廠商入口。

完整選項與影響：[SRS 第 9 節（D-01～D-17）](spec/SRS.md)；安全審查另有 8 項待決事項，見 [SECURITY_REVIEW.md](phase2/SECURITY_REVIEW.md)。
