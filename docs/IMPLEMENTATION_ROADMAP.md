# 團購 ERP 導入路線圖

> 版本：v0.1
>
> 更新：2026-10-28
>
> 原則：文件先行、逐階段驗收、先平行驗證再接管正式流程

## 如何使用這份路線圖

本路線圖把 [ERP 主藍圖](ERP_MASTER_BLUEPRINT.md) 拆成可驗收的階段。日期與人力需等試點群組、技術棧、訂單來源及 Owner 決策完成後再估；在資訊不足前不承諾不可靠的工期。

每一階段只有在 Exit Criteria 全部有證據時才算完成。正式資料遷移、LIVE、公開部署、退款、撥款與權限開放不包含在文件 PR 內，需另行授權與驗收。

## P0｜需求、流程與資料基準

### 目標

先把「什麼是一檔團、誰能看什麼、數字怎麼算、什麼時候算完成」寫成可測規格，避免把現有混亂直接程式化。

### 工作項目

1. 選定一個試點群組與一檔已結案案例。
2. 訪談 Owner、營運 PM、團主、財務、客服／履約與至少一位廠商窗口。
3. 確認角色、資料範圍與高風險操作核准人。
4. 完成十二階段流程、Campaign 狀態機、五個 Gate 與例外清單。
5. 完成核心資料字典：Campaign、Task、Order、Expense、Settlement。
6. 定義 GMV、有效淨銷售、退款、佣金、淨利與資料截至時間。
7. 盤點所有來源試算表、表單、電商平台、手動檔案與通知管道。
8. 產出「既有流程／主藍圖」差異表與 Owner 決策紀錄。

### Exit Criteria

- SRS 由 Owner 明確確認；無未標記的假設。
- 每個狀態有進入條件、退出條件、責任人與允許轉移。
- 每個 KPI 有公式、來源、更新頻率與例外口徑。
- 試點資料來源可取得，且已標示個資、財務與權限風險。
- 不同文件對同一名詞沒有互相衝突的定義。

### Owner 決策

- 試點群組與正式業務 Owner。
- 團主是否可見成本、淨利、退款明細與分潤預估。
- 首版支援的金流模式與訂單來源。
- 既有 Apps Script／Sheets 在過渡期是主系統、從系統或只讀來源。

## P1｜身分、權限與主資料

### 目標

建立所有後續模組可依賴的組織、群組、角色、團主、廠商、商品與稽核底座。

### 工作項目

- 登入、使用者、角色、資料範圍與停權流程。
- Organization、Group、GroupOwner、Vendor、Product／SKU 主檔。
- 不可變 ID、名稱別名、重複偵測與合併流程。
- 欄位驗證、敏感資料分級與後端授權。
- Audit Log：前後值、操作者、時間、來源、Request ID。
- 匯入 Staging 與錯誤待處理佇列。

### Exit Criteria

- 未授權使用者無法從 UI 或 API 讀取其他群組資料。
- 同一來源資料重跑不產生重複主檔。
- 主檔合併、停用與敏感欄位匯出都有 Log。
- 使用去識別化測試資料完成角色與資料範圍測試。

---

## P2｜檔期、狀態機、Gate 與任務

### 目標

讓每一檔團從草稿到結案都有唯一主檔、清楚下一步、責任人與逾期處理。

### 工作項目

- Campaign／CampaignProduct 建立、複製與取消。
- 狀態機與允許轉移；倒退與跳步需原因。
- 五個 Gate 的檢查清單、核准與退回。
- 任務模板、相對日期、依賴、逐檔覆寫與日期連動預覽。
- Blocker、風險、例外、逾期與升級規則。
- 行事曆、今日待辦與檔期管線。

### Exit Criteria

- 一檔試點可完整走過建立、核准、排程、進行、結單與結案模擬。
- 改關鍵日期前能列出受影響任務；確認後才套用。
- 缺資料或未通過 Gate 時無法進入下一狀態。
- 團主與 PM 看到的任務範圍符合權限。
- 每次狀態與日期變更可從 Audit Log 還原。

---

## P3｜業績同步與 Dashboard

### 目標

讓管理者與團主用相同口徑看到可追溯的業績、目標與更新狀態。

### 工作項目

- 訂單／訂單明細匯入介面：CSV、API 或 Webhook。
- 來源 ID、匯入批次、去重、錯誤列、重試與資料截至時間。
- 取消、退款、部分退款與跨期調整口徑。
- 管理者 Dashboard：全局 KPI、檔期管線、風險、排程。
- 團主 Dashboard：自己的檔期、業績、目標、任務與預估分潤。
- 下鑽檔期、訂單與來源批次；每日／結單快照。

### Exit Criteria

- 同一批資料匯入兩次不重複。
- 抽樣訂單可由 Dashboard 下鑽到來源與匯入批次。
- 管理端與團主端對同一檔期顯示相同口徑數字。
- 畫面顯示資料截至時間；同步失敗可見且可重試。
- 與一檔歷史結案數字完成手工對帳並說明全部差異。

---

## P4｜履約、售後與廠商協作

### 目標

把結單後的庫存、出貨、簽收、退款、客訴與廠商回填納入同一追蹤鏈。

### 工作項目

- 結單快照、採購／備貨數量與履約批次。
- 出貨承諾日、實際出貨、追蹤碼、簽收與延誤。
- Refund／Case：退款、部分退貨、運損、瑕疵與客訴 SLA。
- 廠商單一範圍入口、到期／撤銷與回填歷程。
- 履約與售後異常工作佇列；自動通知與人工升級。

### Exit Criteria

- 廠商無法看見其他廠商、其他檔期或內部成本。
- 廠商回填不會直接把入帳或退款標為已確認。
- 一筆部分退款可正確影響淨銷售與預估佣金。
- 延遲、超賣、客訴與運損都有負責人、期限與證據。

---

## P5｜財務、佣金與結算

### 目標

以可重算、可覆寫但不可竄改歷史的方式完成入帳、費用、佣金與批次結算。

### 工作項目

- Invoice／Payment／Expense／Commission／Settlement 資料模型。
- 財務規則版本：稅、折扣、運費、退款、佣金與四捨五入。
- 入帳候選與人工確認；銀行資料首版可採人工匯入。
- 結算草稿、試算、覆寫原因、確認與調整批次。
- 費用憑證、待補件、已納入批次後的鎖定規則。
- 財務 Dashboard 與結算明細匯出。

### Exit Criteria

- 相同來源資料與規則版本可重算出相同結果。
- 覆寫同時保留自動值、覆寫值、生效值、原因與操作者。
- 已確認批次不能直接刪除或改寫；後續差異以調整批次處理。
- 以至少兩個歷史結算案例完成手算與系統雙向核對。
- 金額與狀態的權限測試全部通過。

---

## P6｜遷移、試點與平行運作

### 目標

在不破壞現行流程的前提下，用一個真實群組完成平行運作與一檔結案。

### 工作項目

- 歷史資料盤點、去識別化試跑、名稱／ID／狀態對照表。
- 資料清理規則、未匹配資料與人工判斷清單。
- 遷移前備份、試跑、差異報告、回滾演練。
- 舊系統與新 ERP 雙軌對帳；明確定義主從寫入方向。
- 試點培訓、操作手冊、問題回報與每日巡檢。
- 一檔團從建立到結案的端到端驗收。

### Exit Criteria

- 遷移筆數、成功、失敗、略過與差異都有報告。
- 無真實資料被預設值、測試資料或錯誤欄位映射覆蓋。
- 試點一檔完成端到端結案，數字與現行流程對得上。
- 團主、PM、財務與 Owner 簽署試點驗收或列出明確缺口。
- 回滾步驟已演練且可在目標時間內完成。

---

## P7｜Production Readiness 與上線決策包

### 目標

把正式上線所需的安全、備援、監控、責任與回復能力整理成可核准的決策包。

### 工作項目

- 威脅模型、權限複核、秘密管理、MFA 與外部入口保護。
- 備份、還原、RPO／RTO 與事故演練。
- 系統、Job、同步、失敗佇列、延遲與安全告警。
- 資料保留、個資匯出／刪除與法規檢查。
- On-call／事故責任、維運手冊、服務降級與手工作業方案。
- Go／No-Go 清單、切換與回滾窗口。

### Exit Criteria

- 備份可實際還原，不只確認「有備份」。
- 重大權限、金額、資料遺失與整合中斷情境完成演練。
- 正式資料、通知、外部入口與部署仍需 Owner 最終授權。
- Go／No-Go 會議有完整證據、風險接受人與回滾負責人。

## 建議的第一個開發切片

在 P0 完成後，優先交付一個垂直切片，而不是一次建完所有模組：

```text
建立一檔團
→ 指派 PM／團主／廠商
→ 產生任務與日期
→ 通過 G1、G2
→ 匯入一批去識別化訂單
→ 管理者與團主看到同一口徑業績
→ 產生結案摘要
→ Audit Log 可追溯全部變更
```

這個切片先驗證最重要的資料關聯、權限、狀態、排程與 Dashboard，再決定履約與財務模組的實作細節。

## 共通驗收證據

每個階段至少保留：

- 規格版本與 Owner 決策紀錄。
- 自動測試與關鍵手工驗收案例。
- 權限測試、資料差異報告與 Audit Log 範例。
- 已知風險、未完成事項與回滾方式。
- 實際畫面或 API 結果，但不得包含未遮蔽的個資或機密。
