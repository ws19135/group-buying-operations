## C. 流程與權限（會改變誰能做什麼，所以我沒有擅自改）

| # | 事項 | 現況／我的建議 |
|---|---|---|
| C1 | **廠商調查的職責分離**：目前送審與核准可以是同一人（營運主管同時有 `selection.write` 與 `product.review`） | 建議：核准者不可是送審者（可設定開關）。這會改變核准權限，需你決定；我沒有實作 |
| C2 | 「有風險」的調查題 | 目前只要有一題「有風險」就不能送審、核准。若希望「風險已知並接受」也能核准，需要新增「已接受風險」的狀態與核准人，請決定 |
| C3 | 調查核准後，被新版取代的舊版 | 現在：新版核准後舊版讀取時視為「已被取代」（狀態不改）；若新版之後被撤銷，舊版**不會**自動恢復。是否要恢復？ |
| C4 | 廠商層級調查涵蓋的商品範圍 | 現在：廠商層級的調查適用該廠商所有商品，核准時不記錄商品範圍；新品類（例如日用品廠商新增食品）會被沿用。是否要在核准時列出涵蓋範圍或品類？ |
| C5 | 調查核准有效期的主動提醒 | 目前只在讀取時判定失效，沒有到期前提醒；是否要接通知（需另外同意啟用任何通知）？ |
| C6 | 證據連結的網域白名單 | 目前預設為空（不限制）。正式啟用前建議設定公司核准的雲端網域 |
| C7 | 評估的「補件要求」是否要連動任務 | 目前只是評估上的記錄，不建立任務、不發通知；是否需要 |
