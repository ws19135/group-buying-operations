# 小規模測試團成效 KPI（8 項）：公式、資料來源、期間、完整度

> 狀態：**已建置（顯示與整理，不判定）**。Owner 已於 2026-11-03 裁決 K-1、K-2、K-3（見 §5），本版依決策實作。
> 位置：試用詳情頁（「觸及與導購資料」卡＋「成效 KPI」卡）、選品與試用 → 「測試團 KPI 彙整」分頁。
> API：`GET /api/trials/:id/kpis`、`GET /api/trial-kpis/summary`、`GET／POST /api/trials/:id/reach`、`POST /api/reach-records/:id/void`。
> 程式：`lib/trial-kpi.ts`（純函式）、`lib/trial-reach.ts`、`lib/actual-sales.ts`、`lib/actual-profit.ts`、`modules/trial-kpis.ts`、`modules/trial-reach.ts`、`modules/actual-contribution.ts`。

## 1. 共同規則

| 規則 | 說明 |
|---|---|
| 資料不足 | 沒有可靠資料來源、或分母為 0 時，**顯示「資料不足」與原因，不顯示 0、不推測**。 |
| 資料完整度 | 0～100%：該指標需要的資料有幾成可取得。 |
| 樣本偏小 | 有效訂單少於「V2 設定」的 `minSample.orders` 時加註，不隱藏數字。 |
| 期間 | 本檔期開團日至結團日（尚未結團則到今天）；導購訪客的統計期間需與檔期重疊。 |
| 團主歸因 | 有指定團主的試用：只算歸因到該團主的訂單（金額依歸因比例分攤）；沒有團主：整個檔期。 |
| **K-1 不設門檻** | 不做達標／不達標，不判定是否值得放大銷售；只顯示數值、趨勢、資料完整度與風險提示。 |
| 敏感資料 | 每單貢獻利潤含成本與分潤，只有 `product.cost.read` 看得到；沒有權限者只看到「需成本檢視權限」，連資料不足的原因（會洩漏條款欄位）都不給。 |
| 共用定義 | 訂單、GMV、退款、有效訂單由 `lib/actual-sales` 計算，**KPI 與商業可行性「實際值回寫」共用同一個定義**（見 `TRIAL_KPI_FINANCE_ALIGNMENT.md`）。 |

## 2. 八項指標

| # | 指標 | 公式 | 資料來源 | 目前可算？ |
|--:|---|---|---|---|
| 1 | 有效成交訂單數 | 狀態為 PAID 或 PARTIAL_REFUND 的訂單數 | `orders`（有團主時以歸因分攤） | ✅ |
| 2 | 導購轉換率（CVR） | **有效成交訂單數 ÷ 有效導購訪客數 × 100** | 試用的「觸及與導購資料」（人工填寫）＋ `orders` | ✅ 有可信的有效導購訪客才算；否則資料不足 |
| 3 | 有效平均客單價 | （計入銷售訂單的 GMV − 退款）÷ 有效訂單數 | `orders` | ✅ |
| 4 | 每單貢獻利潤 | **公司貢獻利潤 ÷ 有效訂單數**；公司貢獻利潤＝公司確認收入 − 團主分潤（若由公司支付）− 公司實際負擔的可歸屬成本 | 該檔期「商業可行性」的合作條款（來源須為合約或正式商務條件）＋實際訂單 | ✅ 條款完整且已確認才算；否則資料不足 |
| 5 | 退貨與取消比例 | 退貨（款）比例＝有退款的訂單 ÷ 計入銷售的訂單；取消比例＝已取消 ÷（計入銷售＋已取消） | `orders` | ✅ |
| 6 | 客訴與缺陷率 | 客訴率＝客服案件 ÷ 有效訂單 × 100（每百單）；缺陷率＝試用檢核未通過項 ÷ 已測項 × 100 | `service_cases`（檔期層級）、`trial_checks` | ✅ |
| 7 | 出貨準時率 | 實際出貨日 ≤ 預計出貨日的出貨單 ÷ 有兩個日期的出貨單 × 100 | `fulfillment_batches`（訂單出貨；SHIPPED／DELIVERED） | ✅ |
| 8 | 團主再次合作意願 | 試用結束後由營運人員記錄：願意／尚未決定／不願意 | `product_trials.host_intent`（人工記錄） | ✅ 記錄後顯示 |

## 3. K-2：觸及與導購資料（人工填寫，三種分開）

位置：試用詳情頁「觸及與導購資料」卡；資料表 `trial_reach_records`（migration 018）。**本階段不新增任何外部 API 整合**（LINE、導購短連結、電商平台之後再接）。

| 資料 | 意義 | 可用的來源種類 | 用途 |
|---|---|---|---|
| **潛在觸及人數** | 團主社群規模，例如 LINE 群組成員數 | LINE 群組成員數、團主自行回報、其他 | 只用來另外顯示「群組成員訂單比」；**不是實際觸及** |
| **實際觸及人數** | 平台提供的貼文觸及人數 | 平台貼文觸及、平台統計後台、團主自行回報、其他 | 只顯示，不當分母 |
| **有效導購訪客** | 有可信來源的「不重複」導購訪客數 | 導購短連結不重複訪客、平台統計後台、團主自行回報、其他（**群組成員數與貼文觸及不能標成這項**） | **CVR 的分母（唯一）** |

每筆都記錄：**來源種類與來源說明、統計期間（起訖）、填寫人、填寫日期、資料可信度（高／中／低）**，另有備註（不得含電話或 Email）。

- **CVR ＝ 有效成交訂單數 ÷ 有效導購訪客數**。分母只用「有效導購訪客」。
- **群組成員訂單比 ＝ 有效訂單 ÷ 潛在觸及人數**：另列在 CVR 那一列的分項，標示「不是 CVR、不代表實際觸及」。
- 沒有可靠的有效導購訪客 → **CVR 維持「資料不足」**。「可靠」的判斷：可信度不是「低」、來源種類合規、統計期間與檔期重疊；多筆時採統計期間最晚（再以填寫時間最晚）的一筆。另外：有效成交訂單多於有效導購訪客時視為資料不合理，維持資料不足並說明。
- 建立後**不可修改**（資料庫觸發器保證）；要更正就「刪除」（軟刪除，必填原因，紀錄保留）後重新填。稽核動作 `selection.trial.reach.add`／`.remove`。
- 權限：寫入需 `selection.write`；讀取需 `selection.read` 且在檔期資料範圍內；團主與廠商不能看。

## 4. K-3：每單貢獻利潤（實際值）

**公式**（沿用 `docs/biz-model/04` 代理人口徑，與商業可行性試算共用同一個 `calcFeasibility`，只是改用實際訂單）：

```
公司貢獻利潤 ＝ 公司確認收入 − 團主分潤（若由公司支付）− 公司實際負擔的可歸屬成本
每單公司貢獻利潤 ＝ 公司貢獻利潤 ÷ 有效訂單數
```

**不把收款方與費用負擔方寫死。** 每個合作案／檔期在「商業可行性」分別設定（沿用既有欄位，另新增兩個）：

| Owner 要求 | 欄位 |
|---|---|
| 收款方：品牌／公司／團主 | `cashFlowMode`（品牌自收／公司代收居中／團主代收） |
| 運費負擔方 | `shippingPerOrder`、`shippingBorneBy` |
| 平台及金流費負擔方 | `platformFeePct`／`platformFeePerOrder`、`platformFeeBorneBy` |
| 退款、退貨及相關費用負擔方 | **新增** `returnCostPerRefundOrder`（每筆處理成本）、`returnCostBorneBy` |
| 團主佣金付款方 | `hostPaidBy`、`hostCommissionPct` |
| 公司服務費、經紀費或分潤的計算基礎 | `commissionBasis`（NSV／GMV）、`brandFeePct`、`serviceFeeFixed` |
| 其他實際成本及其負擔方 | `otherVariablePerOrder`、`otherCostBorneBy`、`fixedCost`、`fixedCostBorneBy` |

**只採用已確認的條件**：每個條款的「假設來源」必須是 **合約** 或 **正式商務條件（已確認）**（新增來源種類 `FORMAL_TERMS`）。來源是廠商報價、歷史資料、試用實際或人工估計的條款，不採用。

**以下任一情況 → 「資料不足」並列原因（不顯示暫估，未知成本不當 0）：**
- 檔期還沒有填合作條款，或缺任何必要欄位（含收款方、退款退貨處理成本與負擔方）；
- 任何條款的來源未確認；
- 沒有有效訂單；
- 檔期有多個商品（訂單無法歸屬到單一商品的成本）；
- 只算某位團主、但檔期還有其他團主，且固定費用（公司負擔）或固定服務費大於 0（無法分攤到單一團主）。

**一致性提醒（只讀）**：可行性條款的團主分潤比例，與財務「分潤規則」（結算用）是兩個不同來源；兩者不同或結算規則不存在時，KPI 卡的風險提示會列出（只給有成本檢視權限者）。**不改任何一邊。**

### K-1 彙整頁怎麼看
- **進度**：「已有有效訂單」的小規模測試團數 ÷ 5。達 5 檔只代表「可以整理提交 Owner 審查」，**不會自動啟用任何門檻**。
- **趨勢**：與前一檔（依檔期開團日排序）同一指標的差，不代表好壞。
- **風險提示**：只陳述事實與資料品質（資料不足幾項、樣本偏小、完整度未達 100%、有退貨／取消／客訴、檢核未通過、團主意願不是「願意」、分潤比例不一致），**不是通過／不通過**。
- **提交 Owner 審查時**：請從該頁整理「各指標的實際表現、樣本數、商品類別、團主類型」。
